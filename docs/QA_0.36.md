# OpenBot 0.36: connected daily work and honest evidence

Development candidate, 5 September 2026. This record distinguishes implementation, controlled fixtures, real model execution and unresolved external gates. It is not a Grok Bot head-to-head or a general release certification.

## Implemented

- Brief source settings are encrypted, per teammate, capped at two sources per app/six total. Owner-selected Slack channels (15 messages per channel), current Notion pages and open Todoist projects (20 tasks each) extend morning/weekly work. Only selected extra sources are fetched. Slack windows are 24/72/168 hours for mornings and seven days for weekly review. Notion/Todoist are current snapshots, not change/completion history. Gmail/calendar retain their existing read grants.
- Source receipts include IDs, timestamps where returned, scope, account identity and missing/partial coverage. Threads/files, unsupported/deep blocks, pagination and shortened content cannot become a claim of complete coverage. Changed selections/accounts/grants invalidate cached snapshots and prevent stale report saving. Reconnection requires source reconfirmation, even with the same account display name.
- A source-backed report priority can become an explicit local follow-up. Duplicate clicks are idempotent; done/reopen/dismiss survive restart. No model tool can approve tracking on the owner's behalf. Tracking does not send, create reminders, or change connected tasks. Suggestions come from the ten most recent saved reports; tracking is capped at 250.
- MCP browser sign-in uses the installed official SDK, resource/issuer discovery, public-client registration, PKCE and one-use ten-minute state. Client metadata/tokens/verifiers/discovery are encrypted. Callback success returns to Apps & Tools without leaving the code in the address. Tool discovery and per-teammate grants remain separate. Re-authentication clears grants, and credential refresh cannot undo revocation. All OAuth network destinations use DNS validation/pinning and bounded requests, without automatic redirects. Only same-origin explicitly opted-in loopback OAuth endpoints are permitted for local services. Metadata endpoints with query parameters and pre-registered-client-only providers are not supported by this subset. For local hosts, sign in on the host Mac; phone sign-in needs a reachable configured callback. No relay deployment is implied.
- Google/Slack/Notion/Todoist token-refresh writes are bound to account generation. Disconnecting or changing the OAuth client prevents stale in-flight refresh from restoring credentials. Google's local disconnect takes effect before its bounded revocation request.
- New provider usage receipts distinguish reported values, partial fields and unavailable values per attempt, with recorded child consultations. Cumulative Claude results replace message subtotals; repeated step IDs are deduplicated. No estimates, prices or remaining-plan allowances are invented. Existing numeric budget counters cannot enforce unknown token usage; time/step/output caps remain. Reported cost is not subscription cost, and cached/reasoning categories may overlap. Historical runs have no retroactive receipt.
- `code_benchmark` records a clean baseline and at most two candidates per job. It runs configured regression commands before/after, one excluded warm-up and five command samples, binds receipts to exact commits, hashes selected guarded files and pins the Docker image digest. A changed guard/environment, failed check or incomplete measurement prevents a success verdict. A reduction needs at least 10% lower median and non-overlapping observed ranges; otherwise it is inconclusive. This heuristic is not statistical confidence. Selected guards do not establish full independent test coverage. The runtime is network-disabled, with fixed CPU/memory limits; the owner checkout is preserved. Results are attached as `project-experiment.md`.

## Evidence

- Focused source/connector tests cover opt-in scope, real HTTP adapter shapes with injected responses, dates/IDs, unsafe links, partial content, rate limits, grant/account changes and follow-up persistence. Four separate refresh-race tests cover Google, Slack, Notion and Todoist.
- Four OAuth tests run the real SDK over a local HTTP service: discovery/registration/PKCE, wrong issuer/verifier/replayed/replaced state, saved-state reconstruction, grant changes after sign-in, token redaction/encryption, coalesced refresh and disconnect races. Existing MCP tests retain no-retry uncertain-write, cancellation, schema-change and size guards. This is not consent against a commercial OAuth provider.
- Production API + Chromium at desktop and 390px verifies source selection/save, per-bot rejection, follow-up tracking and restart persistence. Only source-list responses and accounts are synthetic. The real save/read APIs are exercised; no model is dispatched.
- Command experiment tests use real temporary Git worktrees and local fixture commands. They preserve the owner checkout, reject changed guarded tests and deliberately broken candidates, cap experiments, and cover noise/runtime mismatches. They are not live website/functional/accessibility benchmarks.
- The actual OpenCode model/tool/report pipeline passed morning, inbox, meeting and weekly workflows with the owner's explicit `opencode/muse-spark-1.3-contributor-free` connection. Four runs: 32,318 input, 2,084 output and 2,103 separately reported reasoning tokens; 12 model steps, four saved work reports. Synthetic Google/Slack/Notion/Todoist data only. All saved source references were valid; morning/weekly results included extra-app sources; inbox had one unsent draft. No paid fallback or external write. The later usage receipt addition is verified with deterministic runtime tests, not a repeated live-model spend.

Reproduce: `npm run verify`, `npm run test:work-sources-ui`, `npm run test:calendar-routines`, `npm run test:productivity-runtime` (scripted by default), and `npm run test:code-runtime` (real Docker required). Native test/build results and final candidate checks are recorded below after completion.

### Candidate verification completed

- `npm run verify`: **306 tests passed, zero failures**, release/native consistency checks, both TypeScript configurations and production build passed. `git diff --check` passed. No commit, push or merge was performed.
- Production source-picker/follow-up and calendar tests passed at desktop and 390px, including reaching/clicking Save sources at phone width. Four scripted model/tool/report runs passed after usage-receipt integration, each with one work report and one usage receipt. Synthetic Mac fallback and cross-app digest checks also passed; they did not read the owner's apps.
- Real network-disabled Docker checks passed for Node and Python: reproduce the original failing test, repair in an isolated Git worktree, test the exact candidate commit, preserve original checkout and oracle. This exercises the immutable-image runtime change, not the broader website-performance gate.
- Xcode-beta native tests: Mac **19 passed**; iPhone 17 Pro simulator **12 passed, one skipped**, zero failures. Both projects build as **0.36.0 (40)**. No physical phone was used for these checks.
- Packaged and installed arm64 app: deep/strict signature verification, isolated-data startup with system-only PATH, health, production UI, extensions API, JSON 404 and clean streaming shutdown passed. The first copy failed signature verification because its relative symlinks were rewritten; the previous app was automatically restored. Retrying with preserved symlinks passed, and the package test now verifies the destination resource seal too.
- The installed `OpenBot Preview.app` is 0.36.0. Previous app, consistent database and vault-key backups are retained under the owner's Applications folder. No live jobs were interrupted; the existing paused routine was preserved. The live studio on port 4311 returned healthy with the new OAuth controls and no active jobs.
- **Operational caveat:** the Mac became locked, preventing final native-window visual inspection. The existing source-based LaunchAgent did not restart the host after reloading; the studio was brought back online with a foreground development runner. The original LaunchAgent configuration was preserved. Do not treat that manual recovery as proof of unattended restart. Unlock/native visual QA and resolving login-service startup remain open; the installed package's isolated startup check is a different evidence category.
