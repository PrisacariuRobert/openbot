# OpenBot 0.37: reusable workflows, memory and continuity

Development candidate, 5 September 2026. No commit, push, merge or public deployment is implied. Native-window/startup inspection is waiting for the owner to unlock the Mac. The relay remains deferred.

## Implemented and bounded

- Six shared recipes on web, native Mac and iPhone: morning brief, inbox follow-ups, meeting preparation, public page/feed change watch, project bug fix and weekly review. Each exposes prerequisites, output, limits and a safe-example button. Examples use a separate temporary database that cannot inherit `OPENBOT_DATA_DIR`, fixed synthetic source responses and real production primitives. Report interpretations and repairs are prewritten fixtures, not model output. Project examples execute only fixed sample Node programs; ordinary project tasks still use their configured isolated runtime.
- `openbot.recipe` version 1 is a strict configuration-only format: known recipe/version plus concise/expanded and include-drafts preferences, with a canonical SHA-256 integrity check. It allows no free text, URLs, private identifiers, credential fields, browser state or executable payload. Import requires an owner-selected local teammate, previews requirements, grants nothing and creates no task/routine. Repeated import is idempotent. Integrity is not author authentication. Older `openbot.skill` demonstration exports remain a different format and may include private page paths, labels and historical input values; review them before sharing.
- Memory migration preserves legacy notes and adds revision, provenance and expiry. Owner and legacy notes resist agent overwrite. Agent writes are bound to their actual active run, expire after 30 days by default and require a fresh revision for updates. Owner edits/removals require a current revision so an old phone cannot silently undo a correction. Expired notes remain visible for owner review but leave retrieval/new task context; expiry changes the session fingerprint. Conflicts under case/Unicode-normalized note names are visible and excluded from prompt context. Semantic contradictions under different names are not automatically detected or merged. Deleting a note removes future recall, not old chat history or an already running model context.
- In-app suggestion digests are off by default, owner-enabled, at most five items and one new digest per 24 hours after a saved brief. Only the last seven days of suggestions from bounded recent reports qualify. Exact normalized text/source/account identities deduplicate across reports; 90 days of digest identities are retained. Tracking/done/dismissed items are not offered again under the same identity. There is no push notification, external task, send, reminder or new automation. This is not semantic deduplication of differently worded advice.
- Teaching and normal tasks now share the same per-bot browser profile; display mode no longer changes identity. Browser profiles are not shared across teammates or imported from Codex/Chrome. Existing normal profiles are preserved; legacy separate teaching profiles are not copied automatically. New captures never retain field values and drop query/fragment state; secret/OTP fields require owner takeover. Incomplete/deep-link inputs must be supplied again. Saved steps get explicit prerequisites, failure rules and a different-input validation instruction. These rules guide model behavior; they are not a structural scheduling-validation certificate.
- A controlled site benchmark uses actual Chromium, separate cold browser contexts, exact commits, guarded inputs and original functional/keyboard/label/live-status/390px-overflow checks. A deliberately delayed sample improves; the unchanged sample is inconclusive; a faster wrong-total sample fails before being called an improvement. Measurements are complete browser-command durations, including context setup, not Lighthouse or field Web Vitals. Selected accessibility invariants are not a full accessibility audit. Candidates are scripted fixtures, not proof of an autonomous model optimization loop.
