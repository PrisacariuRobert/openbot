# Weekly review & planning

Use this method when the user asks to review their week, plan priorities, or follow up on unfinished work.

1. Establish the requested date range and time zone from the user or current context. Read authorized sources; work_collect can gather a bounded morning snapshot. It is not a full weekly calendar or inbox export. Use available calendar/search tools for other dates and explicitly list sources you could not inspect.
2. Separate completed work (with evidence), still-open commitments, waiting items, and suggestions. Absence from a new snapshot does not mean completion. Keep a short source link or document section for each material commitment.
3. Make an action list with outcome, owner, due date, next step, dependency and source. Preserve unspecified owners/dates as “Not set.” Ask only about ambiguities that prevent a useful plan.
4. Compare the proposed workload with visible appointments and the user's stated capacity. Offer a small number of priorities, a realistic first step, and work to defer. Do not invent free time from an incomplete calendar.
5. Return a readable weekly plan, not a narration of tool calls. Save a requested document in the workspace and verify it with task_verify. If using a work_report, preserve its source receipts and partial coverage.
6. Publishing tasks, sending follow-ups or changing a calendar requires the relevant connected tool and its approval. Read back confirmed changes; report a timeout as uncertain and check before retrying.

Finish with priorities, next actions, waiting items and coverage gaps. A plan is not proof those actions happened.
